## Summary

The linter looks for arithmetic on the low 32 bits of an address without a corresponding carry into the high 32 bits. Its instruction examples, compiled disassembly and generated kernels exercise different ways those addresses appear. Source and disassembly share the parser and analysis, and the existing control-flow graph provides a useful basis for checking instruction ordering.

The analysis remains a bounded heuristic for identifying suspicious sequences. Its copy and search limits do not establish general address correctness.

## Actionable items

### Require the matching high word before each reachable address use

In `projects/hipblaslt/tensilelite/Tensile/Utilities/address_carry_lint.py:367` and line 382 at the submitted head, the scalar/vector scans accept a later carry even when the address is used first or a conditional branch can bypass that carry. For example, `s_add_u32 s8, s8, 64; s_load_dword s0, s[8:9], 0; s_addc_u32 s9, s9, 0` is accepted. A valid unconditional branch to the matching carry can instead be reported.

Commit [`6be02800f34`](https://github.com/newling/rocm-libraries/commit/6be02800f34a88d488181dc4759209c9e6a5873c) follows the existing control-flow graph and tests carry-before-use, conditional bypass and valid cross-branch chains. The audit found that its copied-address handling was incomplete: the preceding suggestion tip [`e931587ab08`](https://github.com/newling/rocm-libraries/commit/e931587ab08b0faa2a9efc753b9603a3f3aaca5e) still accepted this sequence:

```asm
s_add_u32 s8, s8, 64
s_mov_b32 s12, s8
s_mov_b32 s13, s9
s_addc_u32 s9, s9, 0
s_load_dword s0, s[12:13], 0
```

When the low addition overflows, updating `s9` cannot repair the old high value already copied into `s13`. Moving the carry below the load exposes the related use-before-carry case. Both forms were missed by the earlier patch.

Commit [`1151e63cf73`](https://github.com/newling/rocm-libraries/commit/1151e63cf731f1eb66bbfc60a6901bf2c3843f77) replaces the single copied-address Boolean with state tracking pending low-word aliases, registers containing the carried high value, and carry liveness. Each pending alias needs its corresponding high word updated before use; a copy of the corrected high word satisfies that requirement. Overwriting the original low word does not erase obligations on its copies. The relevant helper is `carried_before_use`, line 363 on the audited suggestion branch.

The new parameterized regression covers scalar and vector versions, stale high copies, discarding the original low, conditional paths, and valid copies after carrying. Run it with `pytest projects/hipblaslt/tensilelite/Tensile/Tests/unit/test_address_carry_lint.py -k copied_address_needs_its_own_updated_high_word` in the configured TensileLite environment. On the preceding tip, the six failing cases returned no finding for invalid sequences; the fix reports them and retains the valid cases.

### Include the implicit input of s_addk_i32

At submitted line 414 of the same file, the constant-only exemption treats `s_addk_i32 s8, 64` as having no register input, although it adds to its destination. An uncarried pointer increment followed by `s_load_dword s0, s[8:9], 0` is ignored. Commit [`3838b580396`](https://github.com/newling/rocm-libraries/commit/3838b580396fb183ef2c4771b296ec1275475180) excludes this instruction from the exemption and adds a regression. The corrected exemption is at line 434 on the audited branch.

### Distinguish scalar sources from vector carry writes

In `carry_writes` at submitted line 356 of the same file, operand 1 of a scalar add is a source. The submitted helper treats it like a second destination, as used by vector carry instructions. A valid vector carry held in `s[20:21]` is therefore considered overwritten by `s_add_u32 s30, s20, 1`, which only reads `s20`.

Commit [`1c8c09fc87a`](https://github.com/newling/rocm-libraries/commit/1c8c09fc87ae1e78c4933b7c623edce2039f13ba) limits the second-destination interpretation to vector carry instructions and tests a valid low/high chain with that scalar read between them. The corrected helper is at line 348 on the audited branch.

### Retain branch-target aliases in disassembly

Default objdump output can omit a label aliasing the kernel entry while branches still refer to that label. The resulting control-flow graph loses the backward edge and misses an uncarried address use on the next loop iteration. The affected `disassemble` helper is at line 464 on the audited branch of the same file.

Commit [`e931587ab08`](https://github.com/newling/rocm-libraries/commit/e931587ab08b0faa2a9efc753b9603a3f3aaca5e) adds `--show-all-symbols` and an assembly/disassembly regression with a loop label at the entry address. Original source reports the issue, original disassembly misses it, and corrected disassembly agrees with source.

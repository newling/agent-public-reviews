### Reclaim idle allocations before declaring a memory shortfall

At `projects/hipblaslt/clients/common/src/fast_check.cpp:2030`, called from `projects/hipblaslt/clients/common/include/testing_matmul.hpp:2601`, the guard compares the next case’s entire estimate with HIP free memory without accounting for buffers retained by `memory_pool` in `projects/hipblaslt/clients/common/include/d_vector.hpp:238`. After a large case returns, its buffers remain allocated and reusable. A later case can therefore skip before the allocator gets a chance to reuse or release them.

This occurred in the submitted leading-dimension sweep: a case needing 16.6 GiB skipped with 15.1 GiB reported free after an earlier case had returned a large allocation to the pool. The focused regression needs only a small cached allocation: it requests slightly more than reported free memory, but less than would be available after releasing that allocation. It fails on the submitted code.

Commit [f85cb8d2cd44](https://github.com/newling/rocm-libraries/commit/f85cb8d2cd44c7125c42faa78231047316a24b6b) adds a mutex-protected release of idle pool entries and retries the memory query only after the first query reports a shortfall. It applies to host and device caches, preserves live allocations, and retains genuine shortfall diagnostics. The new regression verifies both the reclaimed capacity and a live buffer’s contents. Later stack layers should inherit this commit on rebase.

## Actionable items

### Stop descendants even after the load leader exits

In `projects/hipblaslt/clients/scripts/sdc_hunt/fast_check_sdc_hunt.py:283`, `stop` breaks when `process.wait` returns after SIGTERM. The leader can exit while a child in its process group ignores that signal. The child then survives the run and can affect later load combinations.

Commit [`7d157cff873`](https://github.com/newling/rocm-libraries/commit/7d157cff87351b74188b731f6533cf54d587c091) sends SIGKILL to remaining members of the group even after the leader has exited. Its regression starts a real child that ignores SIGTERM, reproduces its survival with the submitted cleanup, and verifies that the fix stops it.

### Validate binary paths and nonempty load commands

In `main` at submitted line 388 and `load_command` at line 109 of the same script, the parsed executable and load arguments are not fully validated. `Path('./hipblaslt-test')` loses its `./` prefix, so executing its string performs a PATH lookup and can fail even when that local file exists. Separately, `--load command:` becomes an empty argument list; `run_once` treats it as no background load and can save a passing run under that load label.

Commit [`7c584f1d0f7`](https://github.com/newling/rocm-libraries/commit/7c584f1d0f70d359564dabf896b9e4950f9933e8) resolves and validates the executable and validates load commands before starting a run. The committed tests reproduce both cases and retain the existing failure behavior for skipped or empty test runs.

### Give each invocation a unique log identity

At submitted line 404 of the same script, invocation names have only second resolution. Two invocations appending to the same results file within one second can choose identical failure-log paths, allowing the second to overwrite evidence referenced by the first record.

Commit [`b404ad9f4ce`](https://github.com/newling/rocm-libraries/commit/b404ad9f4ced00bd28b845f57ced4f8a9235bf65) adds a UUID to the timestamp. Its regression fixes the clock to one instant, runs twice, and verifies that both records still point to their original, distinct output.

### Keep custom command arguments out of log filenames

At submitted line 188 of the same script, `run_once` includes the complete sanitized load string in each log filename. A valid `command:` argument containing a Python command with a 300-character comment raises `OSError: [Errno 36] File name too long` when opening the load log, before running the test. The earlier suggestion branch retained this defect.

Commit [`eccee293240`](https://github.com/newling/rocm-libraries/commit/eccee2932407360c2ad83b1040c09cfa42a02049) puts only the validated load kind, such as `command` or `cotenant`, in the filename. The invocation ID and run number already provide uniqueness. The complete command remains in JSON metadata, so shortening the filename does not discard the reproduction details.

On Linux/Python 3.12, adding `CliTests.test_long_load_command_keeps_logs_and_full_metadata` to the preceding suggestion tip [`9ac33a5a429`](https://github.com/newling/rocm-libraries/commit/9ac33a5a429a71472836c33a0266a78671df8c8e) produced this error; the other six tests passed. The committed test can be selected with `python3 projects/hipblaslt/clients/scripts/sdc_hunt/test_fast_check_sdc_hunt.py CliTests.test_long_load_command_keeps_logs_and_full_metadata`. It passes with the fix and checks the full command metadata, a live background process during the run, the saved failure text and the load log.

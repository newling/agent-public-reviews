## How M, N and K change the value of the check

The mathematical error-detection bound is independent of shape, under the usual random-probe assumptions. For an exactly represented product, let the error be `E = D - A*B`. The check compares `D*r` with `A*(B*r)`, so a wrong result passes that probe only if `E*r = 0`. For a fixed nonzero error over the prime field and independent uniform nonzero probe entries, the probability is at most `1/(p-1)`, regardless of M, N or K. This implementation uses `p = 2^61-1` and reproducible seeded probes, plus a left-side probe. Every output participates. Repeating an unchanged seed is not an independent statistical trial.

The computational advantage does depend on shape. A full reference product costs O(M*N*K); the ordinary projection path costs O(M*K + K*N + M*N). For positive dimensions, their work ratio scales like `1/N + 1/M + 1/K`, ignoring constant factors. Actual timings also include modular arithmetic, memory traffic and GPU launches. Input expectations are computed once and reused across solutions, with an O(M*N) scan for each output on the ordinary path.

| Shape | Consequence |
| --- | --- |
| Very small K, especially K=1 | Reading the M*N output is already comparable to computing the product; little or no asymptotic advantage. K=0 reduces to checking C and the epilogue. |
| Large M, N and K | Matrix-sized passes can save substantial work relative to a full host reference. |
| Very small M or N, even with large K | Scanning the long operand can cost the same order of work as the original matrix-vector or dot product. |

Large K also interacts with the exact-arithmetic requirements added in #13013. Accumulator bounds can refuse a dense case before launch. Values outside the output format's exact-integer range require individual K-length reference calculations; sufficiently many can exhaust the slow-path budget. BF16's small exact-integer range makes this particularly relevant. The sparse-K pattern keeps results small, but changes which numerical faults the input can expose.

The [#13013 review](review_pr13013.md) already records a condition guaranteeing full K coverage: `M >= ceil(K/16)`. The submitted BF16 example M=1031, N=519, K=32768 has bucket width 2048. Even after the nonzero-value fix, its sparse mask covers only `16*1031 + 1 = 16497` of the 32768 K positions, about 50.3%. At zero-based K index 1500, every row of A is zero; changing only that row of B leaves the correct product unchanged. This limits the test input's ability to expose such a fault, irrespective of the verifier's detection probability once D is wrong.

This discussion belongs with the algorithm/cost explanation in #12876 and the exactness/pattern trade-offs in #13013. For #13021's stress evidence, a useful addition would be timings for representative small-K, large-K and skinny cases, with expected-value setup separated from per-result checking, plus slow-path/refusal and active-K coverage counts. Those measurements can guide when to use the ordinary reference; no universal K cutoff is justified by asymptotic cost alone.
